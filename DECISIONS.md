## D-001 — Use the official SDK for transport, not a hand-rolled WebSocket

**Decided:** Depend on `@deepgram/sdk` ^5.7.0 and issue Speak through
`client.speak.v2.createConnection({ model: 'flux-rufus-en' })`.

**Overrides:** PRD §5.2 — "Node 22+, zero runtime dependencies. Uses the global
`WebSocket`." The repo now has exactly one runtime dependency.

**Why:** The build goal's SDK USAGE rule is explicit — use the official SDK for
anything it already covers (issuing Speak, reading Warning/SpeechMetadata
frames, Flush/Interrupt) and hand-roll only for genuine gaps, after checking the
current version. Verified against SDK v5.7.0 (latest published, 2026-08-04):

- `src/CustomClient.ts:1609-1674` — `SpeakV2ClientWrapper`, `urlPath: "/v2/speak"`
- Binary audio-frame handling already patched over the autogenerated JSON-only
  Socket class, which is the hard part of this transport
- `src/api/types/Deepgram.ts` — full `flux-*` voice enum

PRD §5.2's zero-dependency stance predates this SDK surface existing. PRD §5.5
already conceded `ws` as "the one dependency this project would ever need"; the
official SDK is the better version of that concession, because it also tracks
frame-shape changes for us through GA.

**Revisit if:** the SDK's v2 speak surface is withdrawn or materially changes
before GA, or a bug in the wrapper's binary handling forces a raw socket. See
SDK_WATCH.md for the gaps still hand-rolled around.

## D-002 — Staging base URL is a required injected config with no production default

**Decided:** `DEEPGRAM_BASE_URL` is read from env with **no fallback**. If unset,
the server refuses to start rather than defaulting to anything. Mocked tests
inject a loopback URL.

**Context:** `DEEPGRAM_STAGING_API_KEY` is present in this environment. A staging
*host* is not — nothing in the env supplies one, and PRD §3/§5.2 name
`wss://api.deepgram.com/v2/speak`, which is production.

**Why no default:** The goal forbids building a convenience path that makes a
production flip easy by accident. A default value is exactly that path. Failing
closed on missing config costs one clear error message and removes the failure
mode entirely.

**Consequence:** Live verification against staging is halted (FLAGS.md F-001).
Step 1's acceptance gate runs against a mocked `/v2/speak` and is unaffected.

**Revisit if:** a staging host is supplied. Nothing in the code changes — set the
env var.

## D-006 — Default voice `flux-rufus-en`, `flux-marcus-en` rejected server-side

**Decided:** As PRD §5.3/§5.4 require. Independently verified rather than taken
on faith, because PRD §8 flags the underlying guidance as suspect.

**Verification** — the shipping catalog in SDK v5.7.0 `src/api/types/Deepgram.ts`
is 12 voices: alexis, bruce, cole, drew, haley, heather, jack, marcus, priya,
renee, rufus, sharon.

Launch WER guidance recommends meghan/rufus/conor/wes and says avoid
brittany/marcus. Cross-referenced: **meghan, conor, wes, and brittany do not
exist in the shipping catalog at all.** Only rufus and marcus do, and marcus is
the one with reported defects.

So `flux-rufus-en` is the only name on both the preferred-WER list and the
shipping catalog — the PRD's claim is exactly right, and it is right by
elimination across a catalog where 4 of 6 guidance names are phantoms. That
makes the guidance itself the problem, not the default. Escalated as FLAGS.md
F-004 with this evidence attached; not resolved here, per PRD §8.
